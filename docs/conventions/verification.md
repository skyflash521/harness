# 検証手順

変更を確定させる前に通す検査の正本。検査の一覧と合格条件を定めるのはこの文書だけで、他の文書は
それらを再掲せずここを参照する。

## 1. 実行する検査

リポジトリルートで次の6つを実行する。すべてエラー0件で合格とする。

| 検査 | コマンド | 対象 |
|---|---|---|
| 静的検査 | `ruff check` | リポジトリ内の Python 全体(gitignore 済みのパスを除く) |
| 記法検査 | `rumdl check` | Markdown の一般的な記法(見出し・リスト・コードブロックまわりの体裁。gitignore 済みのパスを除く) |
| 節参照検査 | `python3 scripts/check_section_references.py` | 追跡下の Markdown に平文の節参照・裸のファイル参照が残っていないこと |
| 循環参照検査 | `python3 scripts/check_reference_cycles.py` | 追跡下の Markdown の参照を辿って元の文書へ戻る経路が無いこと |
| リンク検査 | `lychee --config lychee.toml .` | Markdown のリンク先の実在 |
| 自己テスト | `python3 scripts/run_selftests.py` | 追跡下のスクリプトのうち、自己テストを持つものの判定ロジック |

`ruff check`・`rumdl check` はディレクトリを渡すと対象を絞れる。作業中の確認には絞ってよいが、
合格判定は絞らずに行う。

## 2. フックの動作確認

ハーネスが起動するフックを新設・変更したら、**ハーネスに実際に発火させるまで完了としない。**
自己テストが確かめられるのは判定と、子プロセスとして起動したときの往復までで、登録の形と実際の
イベントでの発火はそこに含まれない。**発火させた場面とハーネスが返した出力を報告に書く。** この
確認は検査一覧に含めない。

**発火させるために、真でない入力をハーネスへ出さない。** 内容の真偽を伴う入力がこれに当たり、確認の
ためであっても、その入力が真になる場面でしか出さない。**真になる場面が来ない判定は未確認のままでよく、
未確認であることを報告に書く**——完了としないのは、真になる場面で確かめられる経路である。

## 3. CI との関係

`.github/workflows/` のワークフローが、全ブランチへの push でこの検査を走らせる。検査を増減させた
ときは、この文書とワークフローの両方を合わせる。
