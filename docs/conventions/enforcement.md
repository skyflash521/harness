# 守らせる機構の規約

このリポジトリが配布するハーネスへ規律を足すとき、**その規律が守られることをどの機構が保証するかの
正本**とする。個々の規律が何を定めるかは扱わない。通す検査の一覧と合格条件は
[検証手順](verification.md)が正本で、本書はそれへ委譲する。

## 1. 適用範囲

`plugins/<プラグイン名>/` 配下へ、エージェントが従うべき定めを新設・変更する変更を対象とする。
規約文書の節、スキル文書・エージェント定義が課す手順のうち、守られたかどうかを問えるものが該当する。
既存の定めの言い換え・参照の追随のように、守らせる対象を増やさない変更は対象外。

## 2. 読まれることだけに依存する規律を足さない

規約は**読まれて初めて効く**。読むかどうかは、その場に立ったエージェント自身の判断に依存する。
`plugins/<プラグイン名>/docs/guidance/` に置いた規約も、スキル文書・エージェント定義に書いた定めも、その依存を持つ。
**この層だけで完結する規律を新設しない。** 足しても増えるのは、守らせる機構を持たない定めである。

新設する規律は、次のどちらかで守らせる。

- **機械**: フック・契約スクリプト・検査スクリプト・CI。ツール呼び出しとターン終了を起点に、
  読む判断を挟まず弾く。
- **他エージェント**: `plugins/<プラグイン名>/docs/rules/` に節として置き、レビューの常設観点かレビュー専用エージェントの
  定義が、その節を名指しで参照する。読む相手が規律を破る当人ではないので、当人が読まなくても効く。

**どちらも当てられないと分かったなら、その規律を足さずに止めてユーザーに諮る。** 守らせる機構を
決められないまま `plugins/<プラグイン名>/docs/guidance/` へ置いて完了としない。

## 3. 機械を先に検討する

**フックが最善**——ツール呼び出しとターン終了を起点に決定論的に弾ける。次が検査スクリプトと CI で、
機械が答えを出せる範囲に限られる代わりに、同じく読む判断を挟まない。**レビューは次善**——依頼文へ
観点を載せる工程を挟むぶん、その工程を踏まない経路には届かない。

上位の手段を採らないと決めてよいのは、[§4](#4-経路が在ることではなく発火することを確かめる)の確認で
次のどちらかが分かったときに限る。**その規律が問う場面に上位の機構の起点が無い**か、**起点は在っても
上位の機構ではその規律の違反を判定しきれない**か。手間の大小で決めない。

## 4. 経路が在ることではなく発火することを確かめる

参照経路が在ること——どこかの文書からその規律へリンクが張られていること——は強制ではない。
**その規律が問う場面で、その機構が起動するか**を確かめる。

- **起点の無い失敗には、まず起点を作れないかを見る。** ツールを呼ばずにターンを終える失敗は、
  ツール呼び出しを起点とする機構の視野に構造的に入らない。
- **レビューへ載せるなら、その規律が問う対象が差分に現れることを確かめる。** 差分に現れない振る舞い
  ——着手しなかった作業、止まらずに進んだ判断——はレビュアーの入力に無い。
