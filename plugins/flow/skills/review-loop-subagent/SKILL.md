# レビュー専用サブエージェント起動の共通基盤

レビュー専用エージェントの定義に従う read-only のレビュー担当を
レビュアーに使う反復レビュー・ループが共有する起動契約と手順。レビュアーの正体に依らない
判断ロジックは [flow:review-loop-judgement](../review-loop-judgement/SKILL.md) スキルが持つ。
Codex をレビュアーに使うループの起動契約は [flow:codex-watchdog](../codex-watchdog/SKILL.md) スキルが
別に持つ。

## 呼び出し元が定める項目

次の2点だけを呼び出し元スキルが定め、以下の手順に当てはめる。
以下「レビュアーエージェント」「固定モデル」は呼び出し元が定めたものを指す。

- **レビュアーエージェント**: 使用するレビュー専用エージェント定義の名前。
  リポジトリを読み差分を自分で取得できること、読み取り専用の確認だけを行いファイルを編集しないよう
  エージェント定義で縛られていること
- **固定モデル**: そのエージェントが frontmatter で固定しているモデルと、その表示名

## 手順0: 起動可否ゲート・対象確認

`flow:review-loop-judgement` スキルの[手順0](../review-loop-judgement/SKILL.md#手順0-起動可否ゲート対象確認)のとおり実行する。

## 手順1: レビュー実行(1ラウンド)

### Claude Code 上で実行するとき

#### ラウンド1(新規起動)

`Agent` ツールで以下を**同期実行**する:

- `subagent_type`: 呼び出し元が定めたレビュアーエージェント
- `name`: このループの間ずっと使う固定の名前(**必須**)
- `run_in_background: false`
- `prompt`: `flow:review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)を満たし、
  [レビュー依頼に含めてはならない内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めてはならない内容レビュアーに検査作業をさせない)(検査をレビュアーに割り当てない・読む量や読み方を指定しない)に
  反する記述を含まないレビュー指示文
- 実行モデル表示名の申告は
  [実行モデル表示名を申告する](../../docs/criteria/review-response.md#3-実行モデル表示名を申告する)が正本で、
  レビュアー定義がこれを持つ
- **規約ファイルの絶対パス**: レビュアーが自分の定義から正本として参照する規約ファイル(常設観点の
  規約・レビュー応答の規約・レビュー依頼の規約)の絶対パスを依頼文に書く
  ([規約ファイルの所在を絶対パスで渡す](../../docs/criteria/review-request.md#5-規約ファイルの所在を絶対パスで渡す))。
  **このスキルファイルから見て `../../docs/criteria/` にある**。**書かずに起動すると PreToolUse フックが
  deny する**

レビュアーエージェントの起動では `model` を指定しない。

#### ラウンド2以降(同じエージェントを継続する)

**新規に `Agent` を起動せず、`SendMessage` の `to` にラウンド1で付けた名前を指定して次ラウンドの
依頼を送る**。エージェントは完了後もその名前で再開でき、前ラウンドの会話コンテキスト——自分が出した
指摘・読んだファイル・受け取った観点と品質基準——を保ったまま続きを処理する。レビュアーが
`SendMessage` を持たないことは継続の妨げにならない: 応答は再開したエージェントの
最終テキストとして呼び出し側に届く。

- 継続の依頼には `flow:review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)が求める前ラウンドの文脈
  (修正した内容・反証した理由・受容したい項目と認否の要求・スコープ外として却下した理由・保留した項目と
  その理由)を渡す。
  **レビュアーは自分が出した指摘を覚えているので指摘そのものの再掲は要らず、各指摘への対応結果と
  今回問うことを書けば足りる**。目的・品質基準・枠も再掲は要らないが、**保持しているものを参照する
  記述は置く**([目的と枠を明記する](../../docs/criteria/review-request.md#1-目的と枠を明記する))。**常設観点は毎ラウンドすべて適用させる**ので、前ラウンドで渡した
  観点をすべて適用して再レビューせよと明記する(観点を減らさない)。[レビュー依頼に含めてはならない内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めてはならない内容レビュアーに検査作業をさせない)
  (検査をレビュアーに割り当てない・読む量や読み方を指定しない)は継続の依頼にも同じく適用する。
- 実行モデル表示名の申告は継続ラウンドでも毎回得る(レビュアー定義が毎回記載する)。
- **応答は `SendMessage` の戻り値としては返らない**。エージェントは背景で再開し、完了時のタスク通知で
  応答が届く。その通知の到着がそのラウンドの完了であり、届く前に同じレビュアーへ次の依頼を重ねない。
- **継続ラウンドは自分で締切を持つ**: ラウンド1と違い `Agent` ツールの戻りが締切にならない。
  送信後に flow プラグイン同梱の
  [wait.py](../../scripts/wait.py) へ[1ラウンドが時間内に終わらないとき](../review-loop-judgement/SKILL.md#1ラウンドが時間内に終わらないとき)が
  定める秒数を渡し、`run_in_background: true` の Bash で
  起動して待つ(**時間で待つ手段はこれだけで、`ScheduleWakeup` はフックが deny する**)。
- **レビュアーの応答が先に届いたら、走っている `wait.py` を `TaskStop` で止めてから次へ進む**。
  **1つ残したまま `[停止: 待機]` と宣言する形は弾かれない**——`待機` は逆に `wait.py` が
  1つ走っていることを要求するので、締切を止めてしまうとその宣言は通らない。
  `[停止: 完了]`・`[停止: 要判断]` で残っている場合と、待機が2つ以上ある場合は弾かれる。
- **締切に達した回はレビュアーがハングしたと判断し、そのラウンドを打ち切る**。締切に達したかは
  `wait.py` の出力の到達時刻で確かめる——待機はプロセスごと打ち切られうるので、**到達前に終わって
  いれば締切はまだ来ておらず、同じ秒数で起動し直す**。**到達したのに応答が無い回で締切を張り直して
  待ちを継ぐ形は禁止**——ハングを検知するための締切がハングを見逃す装置になる。打ち切りは走行中の
  ラウンドを `TaskStop` で止める(対象は再開したエージェントのタスクで、`SendMessage` の戻り値が
  返す再開先のIDで特定できる)。
- **打ち切ったラウンドは取り直し、失敗ラウンドに数える**(締切超過を理由に観点や論点を削らない)。
  取り直し方は[失敗時の扱い](#失敗時の扱い)に従い、ラウンドの中身は `flow:review-loop-judgement`
  スキルの[1ラウンドが時間内に終わらないとき](../review-loop-judgement/SKILL.md#1ラウンドが時間内に終わらないとき)に従う。

### Codex 上で実行するとき

#### ラウンド1(新規起動)

[Claude Code CLI のレビュー](../../docs/guidance/execution.md#claude-code-cli-のレビュー)で、
呼び出し元が定めた固定モデルとレビュアー定義を使って起動する。
指示文の要件・規約の絶対パス・モデル表示名の申告は Claude Code 上のラウンド1と同じとする。
正常終了した JSON の `session_id` を、このループの再開先として保持する。

#### ラウンド2以降(同じセッションを継続する)

`--resume <session_id>` で前ラウンドのセッションを継ぐ。継続の依頼に含める対応結果・目的と枠への参照・
全常設観点の適用・モデル表示名の申告は Claude Code 上のラウンド2以降と同じとする。
新しい応答が完了するまで同じセッションへ次の依頼を重ねない。
監視・締切・打ち切り・結果の取得は
[共通の実行と待機の契約](../../docs/guidance/execution.md)に従う。

### 失敗時の扱い

取り直しは実行元ごとに次の経路を使い、以下の失敗の分類と回数上限を共通で適用する。

- **Claude Code 上**: 同じ名前へ `SendMessage` で依頼を送り直す。継ぐ先が無い場合だけ新規 `Agent` を起動する。
- **Codex 上**: 同じ `session_id` へ `--resume` で依頼を送り直す。再開先が無い場合または
  時間上限で打ち切った場合だけ、新規 CLI セッションを起動する。

再開先が無いこと自体は失敗回数に数えない。新規起動では前ラウンドまでの文脈と指示文一式を渡す。

- レビュアーの起動がエラーで終わる、または応答が契約違反(観点ごとの確認結果を伴わない無指摘の
  一言、**述べられた母集団・件数が差分と明らかに食い違う応答**、編集を試みた形跡、**規約の正本を
  開けないまま本レビューを続けた応答**——規約が見つからない旨を述べて一般的な観点・依頼文の要約で
  代替したもの——等)の場合は失敗ラウンドとして再実行する。
  **失敗ラウンドの取り直しは、まず同じレビューのセッションを継がせる**
  ——依頼は同じラウンドを出し直すもので、失敗の中身がレビュアーの側にあるならその事実を添える
  (観点・論点は減らさない)。
  取り直す経路と、新規起動へ回す条件は上記の実行元ごとの定めに従う。
- **エラー内容が固定モデル自体の利用不可(モデル未対応・権限エラーなど、モデルを名指しする
  エラー)を示す場合は、原因を「<固定モデルの表示名>が使用不可」として明示し、再試行せず直ちに
  ユーザーへ報告して停止する**。
- **応答末尾のモデル表示名が固定モデルを示していない場合は、モデルが黙って代替された疑いとして
  契約違反扱いにし、失敗ラウンドとして再実行する**。
- **レビュアーが本レビューへ進まず差し戻してきた場合は失敗ラウンドに数えない**。差し戻しが明示する
  不備を直した指示文で、同じラウンドを即座に取り直す。
- **エラー内容が使用量上限(利用上限への到達)を示す場合は、[使用量上限に当たったとき](#使用量上限に当たったとき)に従う**。
- **2回連続で失敗ラウンド扱いになったら「問題発生」として停止**し、状況をユーザーに報告する。
  **この停止を、自律進行を止めたくないという推測で飛び越えない**
  ([停止規定は停滞回避の推測に優先する](../../docs/guidance/user-directives.md#4-停止規定は停滞回避の推測に優先する))。
  別のレビュアーで続きを回すことも、ここでいう飛び越えに当たる。

### 使用量上限に当たったとき

使用量上限を示すエラーは、[使用量上限への応答規約](../../docs/guidance/usage-limit-response.md)に従う。
ループ側で加わるのは次の2点だけ。

- **規約が取り直しを定める枠**([実行元全体の枠](../../docs/guidance/usage-limit-response.md#3-実行元全体の枠は時刻を見ずに取り直す))**に当たる回は取り直す**。
  取り直し方は[失敗時の扱い](#失敗時の扱い)と同じ。
- **即時に取り直す枠の上限エラーを返したラウンドを失敗ラウンドに数える**。取り直したラウンドが同じ上限を
  返せば2回連続となり、[失敗時の扱い](#失敗時の扱い)の停止規定が発火する。
