# Codex 反復レビュー・ループ

codex:rescue(read-only)にレビューさせ、Claude が各指摘を実コードで検証して
**修正/反証/受容/保留**に仕分け、再レビューさせる反復ループ。日本語で報告する。

- **前段(レビュー)**: `codex:codex-rescue` サブエージェント(read-only)が指摘を出す
- **後段(判断)**: Claude が各指摘を実コード・仕様書と照合し、修正/反証/受容/保留に仕分ける
  (判断ロジックの正本は [flow:review-loop-judgement](../review-loop-judgement/SKILL.md) スキル)
- **Codex は編集しない**(修正は Claude が行う)。Codex 出力はそのまま信じず裏取りする

レビュアーの正体に依らない判断ロジックは [flow:review-loop-judgement](../review-loop-judgement/SKILL.md) スキルを見よ。
どのループを使うかの選定(既定と、ユーザーの指定の扱い)は
[flow:review-loop-judgement のレビュアーの選定](../review-loop-judgement/SKILL.md#レビュアーの選定どのループを使うか) が正本。
codex を起動してから結果を受け取るまでのハング防止契約は [flow:codex-watchdog](../codex-watchdog/SKILL.md) スキルを見よ。
このスキルはその上に、レビューループ固有の合否解釈・再試行上限・終了判定を定める。

## 導入契約の確認(最初に行う)

本スキルの実行を開始したら、他の何よりも先に[導入契約の確認スクリプト](../../contract/check_adoption.py)を
絶対パスで実行する。**このスキルファイルから見て `../../contract/check_adoption.py` にある**。

```sh
python3 <check_adoption.py の絶対パス>
```

**非0で終わったら、その出力をそのまま示して停止し、[導入契約](../../docs/rules/adoption.md)へ案内する。**

## ユーザー待ちを出さない(無プロンプト運用)

このループは**許可プロンプト等のユーザー待ちを出さずに自走できる**ことを設計目標にする。codex の
起動・監視まわりの無プロンプト運用(companion 起動 glob・watchdog 起動 glob)は
[flow:codex-watchdog の無プロンプト運用](../codex-watchdog/SKILL.md#無プロンプト運用前提) に従う。このスキルが追加で使う Bash コマンドは以下に限る:

- 照合: 読み取り専用コマンド(`cat`/`sed -n`/`grep`/`rg`/`git` 系)。**検証ツール(リポジトリの
  検証手順書が定める各検査。[導入契約 1](../../docs/rules/adoption.md#1-検証手順書))はレビュー中に
  実行しない**([手順2: 照合・仕分け](#手順2-照合仕分け)はコードの読解と読み取り専用コマンドで行う。検証はレビューループの外
  (レビューループの呼び出し元)で別途担保する)
- 結果取得・修正・停止: Read / Edit / `TaskStop` ツール(プロンプト無し)

**複合コマンド(`A && B`、`until …; do …; done`)やインラインのループは許可パターンに一致せず毎回
プロンプトを出す**。新しいコマンドが要るときは狭いパターンでリポジトリの許可設定に追加してから使う
(書き込み系・`sed -i` は登録しない)。

## 手順

### 手順0: 起動可否ゲート・対象確認・可用性確認

`flow:review-loop-judgement` スキルの[手順0](../review-loop-judgement/SKILL.md#手順0-起動可否ゲート対象確認)のとおり
起動可否ゲートと対象を確認する。あわせて `flow:codex-watchdog` スキルの[使用不可の検知と再試行](../codex-watchdog/SKILL.md#使用不可の検知と再試行セッション内で記憶)の
とおり、前ラウンドで記憶した「使用不可」の状態が無いか確認してから[手順1](#手順1-レビュー実行1ラウンド)へ進む(自動復帰・
スキップの判定基準は同スキルが定める)。

### 手順1: レビュー実行(1ラウンド)

`codex:codex-rescue` エージェント(`Agent` ツール、
`subagent_type: "codex:codex-rescue"`)を、[flow:codex-watchdog](../codex-watchdog/SKILL.md) スキルの契約のとおりに
実行する(同スキルが定める契約全体に従う。一部だけを選んで適用しない)。`node` を Bash で直接叩かない。

レビュー指示文には **`flow:review-loop-judgement` スキルの[レビュー依頼に含めるべき内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)をすべて
満たし、[レビュー依頼に含めてはならない内容](../review-loop-judgement/SKILL.md#レビュー依頼に含めてはならない内容レビュアーに検査作業をさせない)(検査をレビュアーに割り当てない・読む量や読み方を指定しない)に
反する記述を含めない上で**、以下のレビュー固有の起動契約を追加する:

- **「codex を read-only で実行し `--write` を付けるな」を明示する**(実行時契約上 codex:rescue は
  既定で `--write`、read-only 明示時のみ読み取り専用)。**ただし注意**: read-only にしても companion の `task` モードはジョブ状態ログを
  codex 起動前に無条件で書くため、`--write` の有無と無関係に EPERM になりうる(`flow:codex-watchdog`
  の[サンドボックス規約](../codex-watchdog/SKILL.md#サンドボックス規約)参照)。EPERM が出た場合はサンドボックスを切らず失敗として扱う。
- **「テスト・静的検査・リンク検査などの検証ツールは実行するな。指摘の検証はコードの読解と
  読み取り専用コマンドの確認だけで行え」を明示する**(read-only 指定はファイル編集を防ぐだけで、
  テスト・検証コマンドの起動までは防がない)。
- **出力契約**(`flow:codex-watchdog` の[エージェント内部の実行契約](../codex-watchdog/SKILL.md#エージェント内部の実行契約companion-呼び出しをバックグラウンド化しない)に追加する形で明記):
  「レビュー結果を応答に必ず含めて返す」ことと、
  [レビュー応答の規約](../../docs/rules/review-response.md)が定めるうち指摘の形・観点ごとの確認結果
  (母集団・件数・類型ごとの内訳)・受容の認否・却下の再指摘・直す要否の一意な明示を依頼文へ載せる。**実行モデル表示名の申告は載せない。**

#### 継続レビュー(2ラウンド目以降)

**レビュアーの文脈を持つのは codex のスレッド**なので、2ラウンド目以降はそのスレッドを継がせ、前ラウンドの
指摘・読んだファイル・受け取った観点を保ったままレビューさせる。**エージェント自体は毎ラウンド新規に
起動する**。

- **スレッド継続で起動させる**: タスク指示文に、前回の codex スレッドを継続する形で起動せよと明記する
  ([codex 起動の作法](../codex-watchdog/SKILL.md#codex-起動の作法誤起動防止)のスレッド継続)。あわせて **companion の出力を JSON 形式で受け取り、
  応答に codex のレビュー本文とスレッドIDの両方を含めて返せ**と指示する(JSON 指定で止まるのは進捗の
  標準エラー出力だけで、watchdog が見るジョブログは従来どおり書かれる)。**この形式指定を省けない**——
  エージェントは companion の標準出力をそのまま返す契約で、JSON 以外の形式ではスレッドIDが標準出力に
  出ない。**指定に使うオプション(`--json`。`--` より前に置く)は、
  他の起動値と同じく呼び出し側が確定値として渡す**(試し打ちは[実行契約](../codex-watchdog/SKILL.md#エージェント内部の実行契約companion-呼び出しをバックグラウンド化しない)が禁じている)。
- **継いだスレッドを起動後に照合する(取り違え検出)**: 継ぐ相手は[呼び出し側が選べない](../codex-watchdog/SKILL.md#codex-起動の作法誤起動防止)。
  **継ぐ回は、返ったスレッドIDが直近に採用したラウンドのスレッドIDと一致しなければ、そのラウンドを
  収束の根拠にせず、次ラウンドを新規スレッドで取り直す**。照合の基準にするため、**ラウンド1から JSON
  形式で起動させ、各ラウンドで返ったスレッドIDを採否を問わず控えておく**。
  **不一致を理由に、返ってきた指摘を廃棄してはならない**——指摘は
  [受け取った指摘を廃棄しない](../review-loop-judgement/SKILL.md#受け取った指摘を廃棄しないラウンドの正当性と指摘の内容を分ける)のとおり
  [手順2](#手順2-照合仕分け)へ通常どおり回し、無関係なスレッド由来の指摘は裏取りの結果として反証で落とす
  (不一致で直すのは次ラウンドの継続先であって、受け取った指摘ではない)。
- **スレッドを継がせない回は、継がないことを明示する**: **ループ最初のラウンド**・失敗ラウンドの
  取り直し・照合不一致の取り直しは新しいスレッドで実行させたいので、タスク指示文に**新規スレッドで
  起動せよ**と明記する(明示しないと[自分の判断で継続される](../codex-watchdog/SKILL.md#codex-起動の作法誤起動防止))。**これらの回は照合も逆向きになる**:
  返ったスレッドIDが**このループでこれまでに返ったスレッドIDのいずれか**と一致したら、継がせない指示に
  反して継がれた回なので、同じくそのラウンドを収束の根拠にせず次ラウンドを新規スレッドで取り直す
  (受け取った指摘の扱いも上と同じで、廃棄せず仕分ける)。ループ最初のラウンドは照合の基準がまだ無く、
  指示の明示だけが防御になる。
- **応答にスレッドIDが無い回は、watchdog が示すジョブログから回収してから判断する**: watchdog の出力の
  `LOG=` が指すログは RUNID で自ラウンドと特定済みで、そこに `Thread ready (<ID>)` が新規・継続の
  どちらの経路でも出力される。**読むのは companion 自身の進捗行(ISO 時刻で始まる行)に限る**——同じログ
  には codex の応答本文がそのまま追記される。**進捗行から一意にIDが得られない回は、継ぐ回も継がない回も収束の根拠にせず、次ラウンドを新規スレッドで取り直す**。**この回も受け取った指摘は廃棄せず[手順2](#手順2-照合仕分け)へ回す**。
- **スレッドを解決できずに起動が失敗した回は、失敗ラウンドに算入せず、新規スレッドで起動し直して続行する**
  ([スレッド継続](../codex-watchdog/SKILL.md#codex-起動の作法誤起動防止)のとおり、このエラーは継げないことだけを意味する)。**このエラーを一度観測したら、
  そのセッションの残りは継がない回として進める。** 継げないことを理由にレビューを止めない。
- **スレッドを継がない回は、レビュー指示文一式(目的・品質基準・常設観点・出力契約)と前ラウンドまでの
  文脈を改めて渡す。**
- **継いだ回は指摘そのものの再掲が要らない**。[前ラウンドの文脈](../review-loop-judgement/SKILL.md#レビュー依頼に含めるべき内容レビュアーに依らない共通要件)として渡すのは各指摘への対応結果
  (修正した内容・反証の理由・受容の認否要求・スコープ外却下の理由・保留した項目とその理由)と今回問うことで
  足りる。
  **常設観点は毎ラウンドすべて適用させる**ので、前ラウンドで渡した観点をすべて適用して再レビューせよと
  明記する(観点を減らさない)。
- RUNID の発行と watchdog の起動は[従来どおり](../codex-watchdog/SKILL.md#watchdog-の起動)。

#### 完了の判定(codex-watchdog の機械的な判定に、レビュー固有の合否解釈を重ねる)

- `flow:codex-watchdog` の[完了の判定](../codex-watchdog/SKILL.md#完了の判定機械的な部分)のとおりエージェント応答/watchdog 通知の先着で分岐した上で、
  レビュー固有の合否解釈を適用する:
  - **エージェントの応答に、codex/companion/app-server が起動失敗・完走不能だったことを示す記述
    (EPERM・初期化失敗・アクセス拒否等)と、タスク内容への回答(指摘列挙・確認結果・分析等)が
    同時に含まれる場合(自己代行)** → **契約違反として無条件で失敗ラウンド扱いにする**。応答内の
    タスク内容は指摘列挙としても無指摘の結論としても一切採用せず(参考にもしない)、新規 RUNID で
    取り直す。「念のため自分で確認した」等の注記が付いていても、codex 自身が完走していない以上
    採用しない([Codex 未完走時の自己代行禁止](../codex-watchdog/SKILL.md#codex-未完走時の自己代行禁止)参照)。**この判定は、失敗の症状が EPERM かつ呼び出し側
    原因の既知パターンに一致する場合であっても変わらない**(自己代行は codex 未完走時にエージェント
    自身がタスク回答を代行した独立の契約違反である)。
  - **エージェントが指摘列挙を返す**(上記の自己代行に該当しない) → 採用([手順2: 照合・仕分け](#手順2-照合仕分け)へ)。
  - **エージェントが観点ごとの確認結果を伴った無指摘の結論を返す** → 無指摘ラウンドとして採用し、
    [手順3](#手順3-終了判定)へ回す。**確認結果の実体を伴わない無指摘の結論(観点ごとに何をどの実装/仕様と
    照合したかが無い、または結論の一言だけ)は契約違反として失敗ラウンド扱いにし、新規起動でやり直す**
    (実体の有無で採否を決め、特定語の有無では決めない)。**述べられた母集団・件数が差分と明らかに
    食い違う応答も同じく契約違反**として扱う(件数は呼び出し側が持つ差分に照らして確かめられる)。
  - **[watchdog 正常終了なのにエージェント応答が来ない場合](../codex-watchdog/SKILL.md#watchdog-正常終了なのにエージェント応答が来ない場合フォールバック)(ログ走査で
    代替する経路)** → **【安全規則】このフォールバックでは無指摘(収束)を確定しない**: 抽出が
    指摘列挙なら参考にしつつ対処してよいが、**無指摘に見えても採用せず失敗ラウンド扱いで新規
    エージェントで取り直す**。**無指摘の確定はエージェントの直接応答(観点ごとの確認結果を伴った
    無指摘の結論)でのみ行う。**
  - **エージェントが companion を起動せず差し戻す応答を返す**(`flow:codex-watchdog`・
    `flow:review-loop-judgement` など起動契約が定める差し戻し全般。禁止記号違反・目的記載不備等、
    理由は問わない)→ **失敗ラウンドとしてカウントしない**(下記[再試行と継続](#再試行と継続このループの再試行上限)参照)。差し戻し応答が明示する不備を修正した上で、新しい
    RUNID で同じラウンドを即座に取り直す。
  - **`flow:codex-watchdog` が stall・no-start・wall-cap・失敗・エージェントの失敗報告・早期復帰等を
    検出した場合** → `flow:codex-watchdog` の[失敗は症状のラベルでなく原因で仕分ける](../codex-watchdog/SKILL.md#失敗は症状のラベルでなく原因で仕分ける)のとおり、
    症状のラベル(stall/no-start/wall-cap 等)だけで機構障害と決めつけず原因を確認する:
    - **原因が呼び出し側の起動コマンド組み立てミス(相対パス・誤ったパス推測・`--` 省略・RUNID
      不一致等)だと判明した場合** → **失敗ラウンドとしてカウントせず、原因を取り除いた上で上限を
      設けずに新規エージェントで再試行する**(下記[再試行と継続](#再試行と継続このループの再試行上限)参照)。
    - **Codex/companion 側が実際に応答不能・処理停止していると判断できる場合、または原因が
      判明しない場合** → 失敗ラウンド扱いで新規エージェントによる取り直しへ。
    - stall・wall-cap での取り直しでは、`flow:review-loop-judgement` の[1ラウンドが時間内に終わらないとき](../review-loop-judgement/SKILL.md#1ラウンドが時間内に終わらないとき)に
      従う。
- 補足: 「短時間で完了した無指摘」や、確認結果の実体を伴わない無指摘の結論(結論の一言だけ)は、
  契約違反(失敗を無指摘と詐称)の疑い。**失敗ラウンドとして新規起動でやり直す**。再試行で正規結果と
  認めるのは、**各観点の確認結果を伴った上で指摘が無い旨を結論してきた場合に限る**(再び実体の無い
  結論だけならまた失敗ラウンド)。

#### 再試行と継続(このループの再試行上限)

- **失敗ラウンドの取り直しでは codex のスレッドも継がせず、新規スレッドで取り直す**(新しい RUNID を
  発行し、[継続レビュー](#継続レビュー2ラウンド目以降)のとおり新規スレッドで起動せよと明記した上で、前ラウンドまでの文脈——修正済みの
  要約・却下理由・受容理由・保留した項目とその理由・今回問うこと——とレビュー指示文一式を渡す)。
  **取り直したラウンドを採用できたら、そのラウンドのスレッドIDが以後の照合の
  基準になる**。
- **2回連続で失敗ラウンド扱いになったら「問題発生」として停止**し、状況をユーザーに報告する
  (自律進行を止める)。**この停止を、自律進行を止めたくないという推測で飛び越えない**
  ([停止規定は停滞回避の推測に優先する](../../docs/guidance/user-directives.md#4-停止規定は停滞回避の推測に優先する))。
  別のレビュアーへ切り替えて続きを回すことも、ここでいう飛び越えに当たる。**ここでの「失敗ラウンド扱い」は、新規起動でやり直しに回る全ての失敗を指す**
  (`flow:codex-watchdog` が判定する失敗に加え、自己代行の検出・確認結果を伴わない無指摘の結論・
  フォールバックでログ走査が無指摘に見えた場合の不採用 など)。**呼び出し側のレビュー指示文の組み立てミスによる
  差し戻し(上記[完了の判定](#完了の判定codex-watchdog-の機械的な判定にレビュー固有の合否解釈を重ねる)参照)は、この失敗ラウンド扱いに含めない**。不備を修正した指示文で
  新しい RUNID を発行し即座に取り直す。ラウンド数に上限は設けず、暴走は「数ラウンド連続で新規解消
  なし」の千日手と、この連続失敗停止の二つで止める。
  **差し戻しには別立ての連続回数上限を設けない。**
  **[スレッドを解決できずに起動が失敗した回](#継続レビュー2ラウンド目以降)も
  この失敗ラウンド扱いに含めない**。**照合の不一致・スレッドIDを特定できないことを理由に次ラウンドを
  新規スレッドで取り直す回は、指摘を仕分けたうえでこの失敗ラウンド扱いに数える**(原因が呼び出し側の
  起動コマンド組み立てミス——ラッパー指示が継続オプションの付与を塞いだ等——だと確認できた回には
  下記の除外が掛かる)。
- **原因が呼び出し側の起動コマンド組み立てミスだと判明した失敗(stall/no-start/wall-cap 等の症状
  ラベルであっても、上記の照合の不一致・スレッドIDの特定不能であっても)も、この失敗ラウンド扱い・
  2回連続停止のカウントに含めない**。**EPERM は
  [起動コマンドの既知の不備パターン](../codex-watchdog/SKILL.md#起動コマンドの既知の不備パターンチェックリスト)に起動コマンドが一致すれば同様に除外
  するが、この一致は不備の存在を確定するのみで、それがEPERMの直接原因であることまでは要求
  しない**(下記参照)。この種の失敗にも連続回数上限を設けない。**EPERM もこれと同じく回数上限を設けない**([flow:codex-watchdog](../codex-watchdog/SKILL.md#eperm-は呼び出し側の失敗と推定する既定と手順) 参照。対策を講じたうえでの再試行を、再発を理由に通常の失敗
  ラウンド扱いへ倒すことは、この規律の目的に反する)。呼び出し側は直前の失敗原因(相対パス・
  誤ったパス推測・`--` 省略・RUNID 不一致・
  `--cwd` 省略やスペース区切り2トークン形・中間変数経由での起動コマンド組み立て等)を取り除いた
  上で、上限なく新規エージェントで再試行する。**再試行時のタスク指示文には、今回特定した具体的な
  不備そのものを名指しした禁止文を必ず追加する。一般論の「標準形で起動せよ」のみを付けて無対策の
  まま再試行することを禁止する**。**この判定(呼び出し側原因か機構障害か)を裏付けなく毎回
  「呼び出し側原因」に倒さない**: エージェントの報告・ジョブログから原因を確認できない場合は
  通常の失敗ラウンドとして扱う(原因不明を無条件リトライの免罪符にしない)。**ただし EPERM に
  ついては、`flow:codex-watchdog` の[EPERM は呼び出し側の失敗と推定する](../codex-watchdog/SKILL.md#eperm-は呼び出し側の失敗と推定する既定と手順)の手順(ジョブログ本文
  ——ジョブ状態ログの書き込み自体がサンドボックス制限で拒否され参照できない場合はエージェント
  報告の起動コマンドと生のエラー出力——と起動コマンドを[起動コマンドの既知の不備パターン](../codex-watchdog/SKILL.md#起動コマンドの既知の不備パターンチェックリスト)と照合する)を実際に
  実施してから結論する。この照合を省略して
  いきなり「原因不明」に倒すことを禁止する**(照合の結果[起動コマンドの既知の不備パターン](../codex-watchdog/SKILL.md#起動コマンドの既知の不備パターンチェックリスト)のいずれにも一致しない
  場合に限り、通常の失敗ラウンドとして扱ってよい)。
