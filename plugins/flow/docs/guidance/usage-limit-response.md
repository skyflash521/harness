# 使用量上限への応答規約

使用量上限(利用上限への到達)で処理が失敗したときに、**次に何をしてよいかの正本**とする。どの
モデル・プロセスがどの枠に属するかも本書が定める。

## 1. 適用範囲

**使用量上限を理由に処理が失敗した場面すべて**を対象とする。レビューの場面に限らない——自分が直接
受けた失敗、サブエージェントが返した失敗、委譲先のプロセスが返した失敗を問わない。

**対象外は、枠が尽きたのではなく使えないことを示す失敗**(モデルの利用不可・モデル未対応・権限
エラー)である。これらは実行中のスキルの定めに従う。

## 2. 尽きた枠で分ける

処理が消費していた枠が次のどれかを見分ける。**見分けが付かないなら Claude 全体の枠として扱う**
(時刻を見ない側に倒す)。

- **Claude 全体の枠** — 呼び出し側の自分と同じ枠から引かれるもの(Opus・Sonnet・Haiku 等)
- **モデル専用の別枠** — Claude 全体の枠とは別に消費されるもの(Fable)
- **別プロセスの枠** — Codex

## 3. Claude 全体の枠は時刻を見ずに取り直す

**リセット時刻を読み取らない。残り時間を計算しない。出力へ書かない。時刻を根拠にユーザーへ諮らない。**
エラーや通知が時刻を示していても使わない。

**自分がその通知を読んで考えて書けている事実が、この枠がいま効いていない証拠である**——効いていれば
動けない。時刻は行動を変えない情報で、調べた時点で無駄が確定する。失敗した処理はそのまま取り直す。
**取り直しても同じ失敗が返ることだけが意味のある信号**で、そのときも時刻は要らない。何回で諦めるかは
実行中のスキルの停止規定が定め、**その規定が無い場面では、取り直して同じ上限が返った時点で報告して
止まる**。

## 4. モデル専用の別枠は繰り返さず報告して止める

こちらが動けていても、その枠だけが尽きていることはありうるので、動けていることは証拠にならない。
一方で**取り直しても同じ上限に当たるだけなので、再試行を繰り返さない**。上限に達した旨を報告して
止める(エラーが再試行可能になる時刻を示していれば添えてよい)。

## 5. 別プロセスの枠はそのプロセス向けの手順に従う

Codex は別プロセスなので、こちらが動いていても向こうが止まっていることがありうる。リセット時刻を
読んで待つ手順は [flow:codex-watchdog の使用量上限で待つときの手順](../../skills/codex-watchdog/SKILL.md#使用量上限で待つときの手順)が正本。**この待機の手順を
Claude 全体の枠へ持ち込まない。**

## 6. 上限を理由に指定を動かさない

どの枠でも、上限は指定を動かす根拠にならない([指定は自分の判断で動かさない](user-directives.md#2-指定は自分の判断で動かさない)が正本)。
