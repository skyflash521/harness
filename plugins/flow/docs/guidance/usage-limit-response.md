# 使用量上限への応答規約

使用量上限(利用上限への到達)で処理が失敗したときに、**次に何をしてよいかの正本**とする。

## 1. 適用範囲

**使用量上限を理由に処理が失敗した場面すべて**を対象とする。レビューの場面に限らない——自分が直接
受けた失敗、サブエージェントが返した失敗、委譲先のプロセスが返した失敗を問わない。

**対象外は、枠が尽きたのではなく使えないことを示す失敗**(モデルの利用不可・モデル未対応・権限
エラー)である。これらは実行中のスキルの定めに従う。

## 2. 枠は次の順で決める

**先に経路で分け、残りをエラー本文の名指しで分ける。** この順のとおりに判定し、他の材料を混ぜない。

1. **実行元と異なる製品への依頼なら、[別プロセスの枠](#5-別プロセスの枠はそのプロセス向けの手順に従う)。**
   Claude Code から Codex、Codex から Claude への依頼が該当する。
2. **実行元と同じ製品への依頼、または自分が直接受けた失敗なら、[実行元全体の枠](#3-実行元全体の枠は時刻を見ずに取り直す)。**
   Claude Code から Claude、Codex から Codex への依頼が該当する。
   ただし、エラー本文が Fable を名指ししているときだけ、
   [Fable 専用の別枠](#4-fable-専用の別枠は繰り返さず報告して止める)として扱う。

**名指しとは、尽きた枠のモデルが Fable であるとエラー本文が述べていること**(`Fable` / `fable` /
`claude-fable-…` が、上限に達した対象としてその文に現れること)をいう。**エージェント名・スキル名・
起動時に自分が付けた名前・ファイルパスの一部として現れる `fable`**(`flow:fable-reviewer`・
`fable-review-loop` など)**は名指しに数えない**。

**本文の名指し以外を判定に使わない。** 失敗した呼び出しのモデルが Fable であること・実行中のループが
Fable のループであること・エージェントの名前は、いずれも根拠に使わない。

## 3. 実行元全体の枠は時刻を見ずに取り直す

**リセット時刻を読み取らない。残り時間を計算しない。出力へ書かない。時刻を根拠にユーザーへ諮らない。**
エラーや通知が時刻を示していても使わない。

失敗した処理はそのまま取り直す。**取り直すときに、積み上げた文脈を捨てない。** 名前で再開できる
サブエージェントのように**継続できる経路なら、継続のまま同じ依頼を送り直す**。
何回で諦めるかは実行中のスキルの停止規定が定め、**その規定が無い場面では、取り直して同じ上限が
返った時点で報告して止まる**。

## 4. Fable 専用の別枠は繰り返さず報告して止める

**再試行を繰り返さない**。上限に達した旨を報告して
止める(エラーが再試行可能になる時刻を示していれば、そのまま添えてよい)。

## 5. 別プロセスの枠はそのプロセス向けの手順に従う

別プロセスの上限は失敗ラウンドに数えない。待機と取り直しは
[実行と待機の契約](execution.md#4-使用量上限と使用不可の記憶)に従う。

## 6. 上限を理由に指定を動かさない

どの枠でも、上限は指定を動かす根拠にならない([指定は自分の判断で動かさない](user-directives.md#2-指定は自分の判断で動かさない)が正本)。
