# 着手・継続判断規約

自分の判断で作業へ着手してよいか、始めた作業を続けてよいかの**正本**とする。着手すると決めた作業を
どの手順で進めるかは定めない。

## 1. 適用範囲

**着手するかどうか、始めた後に続けるかどうかを自分で選べる作業**を対象とする。未解決事項・
残課題の一覧に載っている項目、自分の走査や動作確認で見つけた不備、思いついた改善が該当する。

**ユーザーが名指しで依頼した作業は対象外。** 本書を根拠に打ち切らない。依頼された作業の価値に
疑いがあるなら、疑いを述べたうえで依頼どおり
進める。

## 2. 困りごとを一文で言えないなら着手しない

着手前に、**誰が・どの操作で・どう困るか**を一文で言う。言えないなら着手せず、**打ち切ると決めて
理由を残す**([対処の三つの終わり方](defect-followthrough.md#2-対処の三つの終わり方))。言えないこと
自体はユーザーに諮る理由にならない——諮ってよい場面の定めは同節が正本で、本書は定めない。

- **一覧に載っていることは着手してよい理由にならない。** 未解決事項・残課題として記録されている
  項目は「まだ判断していない」という意味であって、「やるべき」という意味ではない。記録されて
  いることを価値の判断と取り違えない。
- 一文は**困る相手と経路まで**言う。「表示が乱れる」では足りず、誰のどの操作でそれが起きるかを
  言う。言ってみて、その経路を通る利用者が居ない(自動処理の側は影響を受けない、人が触らない
  画面である等)と分かるなら、それは着手しない理由である。
- **安く直せることは価値の代わりにならない。** 手間が小さいことと、直す意味があることは別である。

## 3. 原因を裏取りしてから対策を書く

見当をつけただけの原因で実装を始めない。

**原因が定義・仕様から導出で確定できるなら、その導出が裏取りにあたる。** 導出で確定できるものに
まで実測を課さない。導出と実測の線引きは
[計算で確定できるものは計算で確定させる](../rules/numeric-evidence.md#3-計算で確定できるものは計算で確定させる)が
正本で、本節が禁じるのは、どちらの裏取りもせずに見当で対策を書くことである。

**検査・ガードに止められた原因も同じ扱いとする。** 止められた理由を確かめる前に、通すための
書き換えを組み立てない([対策を決める前に原因を確かめる](verdict-handling.md#3-対策を決める前に原因を確かめる))。

**どちらの裏取りも用意できないなら、実装ではなく判断へ進む**——打ち切ると決めて理由を残す。諮るのは
その場面が[諮ってよい区分](defect-followthrough.md#2-対処の三つの終わり方)に当たるときだけである。裏取り
できないことは、見当で書いてよい理由にならない。

## 4. 空振りしたら手段でなく価値を問い直す

調査・計測が無効に終わったら、**手段を作り直す前に、続ける理由がまだあるかを確かめる**。無効に
終わった時点で問うべきは「どう測るか」ではなく「そもそも測る価値があるか」である。

**費やした手間は価値を上げない。** 空振りが続くときは、
手段の不備だけを疑わず、[§2](#2-困りごとを一文で言えないなら着手しない)の一文を言い直して
確かめる。
