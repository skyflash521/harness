# Codex 上の実行と待機

Codex 上でスキルを実行するときは、この文書を共通の起動・監視・停止契約とする。
スキルの目的、起動可否、失敗の再試行回数、レビューの結末は各スキルの定めに従う。

## 1. 起動

flow スキルの着手前に、同梱の
[導入検査](../../contract/check_adoption.py)を
`python3 <check_adoption.py の絶対パス> --host codex <リポジトリルート>` で実行する。
終了コード0を確認してから着手する。不足があれば
[導入契約](../criteria/adoption.md)へ案内して停止する。

シェル実行ツールの作業ディレクトリを対象リポジトリに設定し、委譲先の CLI を直接起動する。
同梱スクリプトで機械検査する場合は、その冒頭にある呼び出し契約に従う。
指示文は UTF-8 の標準入力で渡す。
応答は標準出力から受け取り、後続の呼び出しにもメモリ上の文字列を渡す。
シェルまたはプロセス実行 API で受け渡し、入力・応答の中継用ファイルは作らない。

### Claude Code CLI のレビュー

`claude -p --safe-mode --model <指定系統> --permission-mode dontAsk --tools Read,Grep,Glob
--allowedTools Read Grep Glob --disallowedTools Edit Write NotebookEdit Bash --output-format json`
を起動する。初回は `--append-system-prompt <レビュアー定義の本文>` を加える。
定義の frontmatter を除き、Bash による差分取得は標準入力に含まれる資料を読むことへ読み替える指示を付ける。
次ラウンドは `--resume <session_id>` を加え、定義を再付与しない。

起動前に読み取り専用の `git -c core.quotepath=false diff --no-ext-diff --no-textconv <比較の基点>`、
`git -c core.quotepath=false status --short --untracked-files=all`、`git -c core.quotepath=false ls-files` を取得する。
目的・枠を含む指示文の後ろへ、これらを実行指示でないレビュー資料として区切って付ける。
資料は毎ラウンド取り直す。Glob・Grep が使えない場合は一覧から所在を特定して Read で読む。

## 2. 監視と停止

実行ツールがプロセスのセッション ID を返したら、同じ ID を使って出力と終了コードを取得する。
実行ツールが出力を返すたびに進行状況を確認し、終了していなければ同じセッションの取得を続ける。
ツールが返す ID と委譲先の応答にあるセッション ID は別物で、取り違えない。

CLI の起動を同梱の `skills/run-and-bench/run_capped.py` で包む。
`python3 <run_capped.py の絶対パス> <呼び出すスキルの上限秒数> -- <CLI と引数>` の形を使う。
フックもスキルが定める上限以下での起動を検査する。
外側から締切を重ねず、終了コード124を時間上限の失敗として扱う。
ユーザーが中断を指示した場合は、その実行ツールが提供する中断操作で対象プロセスを止め、
終了を確認する。

## 3. 結果

終了コード0と応答の完了を確認してから、依頼先の回答として採用する。
Claude Code CLI は JSON の `is_error` が偽であること、`result` と `session_id` が在ることを確認する。
固定モデルのレビューは `modelUsage` と応答末尾のモデル表示を照合する。
Codex CLI は JSONL の `thread.started` から ID を取得し、`turn.completed` が在ること、
`turn.failed`・`error` が無いことを確認する。最後の `item.completed` の `agent_message` が回答である。
継続時に `thread.started` が無ければ指定した ID を使う。本文が無い応答は失敗とする。
失敗した応答や部分出力を、呼び出し側の判断で成功へ読み替えない。
起動失敗・時間上限の取り直しは、呼び出したスキルの回数上限に従う。
モデル情報が確認できない・指定モデルと違う・利用できない場合は代替せず停止して報告する。
再試行でも同じモデルと実行モードを保つ。

## 4. 使用量上限と使用不可の記憶

Codex の応答が使用量上限を示したら、エラー本文に再開可能な時刻があるか確認する。
時刻が曖昧、タイムゾーンが不明、または記載が無い場合は、応答を添えて報告し停止する。
時刻を特定できる場合はローカル時刻へ換算し、
[wait.py](../../scripts/wait.py) にそのスクリプトの呼び出し契約どおり渡す。
待機も同じ実行ツールのセッション ID で監視し、正常終了と到達時刻を確認した後、同じ依頼を取り直す。
待機スクリプトが上限超過を返したら停止して報告する。

モデルの使用不可や CLI の不在・認証不足で停止した事実は、同じセッション中に保持する。
同じ原因が解消したことを、コマンドの所在または認証・モデルの利用状態で確認するまで同じ起動を
繰り返さない。`codex:setup` は呼ばない。使用量上限は使用不可の記憶へ入れない。
