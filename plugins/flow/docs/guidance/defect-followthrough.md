# 不備の後始末規約

作業の過程で見つかった不備(誤り・不具合・積み残し)について、**どうなっていれば対処済みと言えるか
の正本**とし、あわせて**ユーザーの応答を待って止まってよい場面の正本**とする(止まる場面は不備の
後始末に限らない)。

## 1. 適用範囲

見つかった不備すべてを対象とする。ユーザーに指摘されたもの、自分の走査で見つけたもの、実行・
動作確認で踏んだもの、レビューで挙がったものを問わない。**見つけた経路は対処の要否を変えない。**

## 2. 対処の三つの終わり方

不備は次のいずれかの状態で終わっていること。

- **直した。**
- **打ち切ると決め、直さない理由が最終報告に残っている。**
- **ユーザーに諮り、その判断を待っている**(諮るとは、ユーザーの応答を待つために作業を止めることを
  いう。どの時点で止めるか——その場で止めるか、蓄積して区切りで止めるか——は実行中のスキルの規定に
  従う)。

**所在を報告して先へ進むことは、この三つのどれでもない。** 停止せずに報告へ書いただけの項目は
**誰にも渡っていない**ものとして扱う。「作業範囲外だが所在は報告した」で終えた項目は、対処されて
いない項目である。

**未解決事項・残課題の一覧へ書くことも、対処の代わりにならない。** 一覧へ載せる項目についても
上の三つのいずれかを同時に決める。

**諮ってよい場面は次の4区分だけ**で、実行中のスキルの停止規定がさらに狭めるならそちらに従う。

- **要求仕様**: ユーザーの決めた値・方針・スコープ・受入条件が変わる。**変わる先を、実在する
  仕様書・計画書・台帳の箇所として名指しできることが条件**——名指しできないなら、決まっていないことを
  いま決める場面であり、それは実装の設計に当たる。
- **指示不明**: 依頼の対象・入力がユーザーにしか無く、推測で決めると別のものを作る。**選べる案が
  複数あることは指示不明ではない。**
- **停止規定**: 規約またはスキルが命じる停止が実際に発火した(千日手・規定回数の連続失敗・使用量
  上限など)。まだ発火していない規定は根拠にならない。**ユーザーが出した禁止や明示指定が作業を妨げ、
  その解除・変更なしには進めない場面もこれに当たる**。
- **操作承認**: 取り消せない操作・外部へ及ぶ操作の承認が要る。

**実装の設計・段取り・作業量・レビュアーが諮れと述べたこと・既定や選択肢を書けること・裏取りを
用意できないことは、どれも区分に当たらない。** 区分に当たらない場面で選べるのは「直す」か「打ち切ると決めて理由を残す」の二つで
あり、報告へ回すことは選択肢に入らない。**規約を根拠に止まろうとするなら、その節が置いている条件を
最後まで読む**——多くの節は停止を許さない場面を自ら除外しており、除外に当たるなら諮るは選べない。
**節が除外を置いていないときは、上の区分外の列挙が優先する。** 「〜なら諮る」と書いてある条項でも、
その場面が区分外に当たるなら諮らない。

## 3. 迂回は不具合の対処ではない

実行・動作確認で対象側の不具合を踏み、自分の道具・手順の側でそれを避けて先へ進むことはあってよい。
ただし**避けたことは、その不具合の対処ではない。** 踏んだ不具合は
[対処の三つの終わり方](#2-対処の三つの終わり方)のいずれかで終わらせる。

不具合の原因まで到達していたなら、**その原因が、既知の未解決事項として記録されている項目と同じ
ものかを突き合わせ、突き合わせた結果が記録に反映されている**こと。同じなら判明した原因を
その項目へ、別なら新規の項目として残す。自分の道具が困らなくなったことは、突き合わせを省く理由に
ならない。

**検査・ガードに止められたときは、避けること自体が禁じられる。** 検査が名指しした不備が成果物の側に
実在するならそれを直すのが対処だが、**不備が無いまま通すために成果物を書き換えることは迂回ですらない**。

## 4. 未解決を残したまま完了としない

計画・ステップ・作業を完了として記録・宣言してよいのは、**その範囲に、
[対処の三つの終わり方](#2-対処の三つの終わり方)のどれも決まっていない項目が無いとき**に限る。
動作確認で観測した挙動は、記録した時点では未対処である。一覧に載っていることを完了の根拠にしない。

**手番を返す完了の宣言について、その範囲はセッションで受けた指示の全部である。** 自分の直近の作業が
終わったこと・コミットが成立したこと・作業ツリーが空になったこと・検査が全部通ったことは、いずれも
その段が終わったことしか意味しない。**動詞が列挙された指示は列挙の全部が済むまで、停止条件が
書かれた指示はその条件の各項が満たされるまで、完了ではない。**

**その全部が済んだことは、発言1件につき1行で記録に残す。** 済ませたら
`対応済み: <その発言から引いた文字列>` の1行を書く。引く文字列はその発言の原文からそのまま写し、
**1行が済ませるのは発言1件**である。**書いてよいのは、その発言が求めていることが全部済んだとき**で、
答えを求めただけの発言なら答えた時点で書けるが、直せと求めている発言は直すまで書けない。計画書の
ステップに現れない指示——会話で受けた依頼・作業中に割り込んだ指示・問いかけ——もこの記録の対象で、
ステップを消化したことはそれらを済ませたことにならない。一度手番が戻った完了より
前の発言は、受け取ったユーザーが続きを述べている以上、改めて記録しなくてよい。

**割り込みで入った指示は、それ以前の指示を消さない。** 割り込みの作業が終わったら、割り込み前に
受けていた指示へ戻って作業を再開する。**後から別の作業を頼まれたことは、取り消しではない。**

**ただし、割り込みが質問であれば答えて手番を返す。** 止まらなければユーザーは回答を見られない。
このとき使う宣言は完了ではなく `[停止: 応答]` で、これは「ユーザーに問われたことへ答えたので、
答えを届けるために手番を返す」ことを述べる。**ユーザーが問うた部分を原文のまま復唱する1行を添える**
——書いた文字列は直近のユーザー発言と突き合わされるので、言い換えず、そのまま写す。
問われていないならこの宣言は使えない。**この宣言が成り立つ条件は問われたことだけで、済んでいない
指示が残っているかは問わない。**
**復唱は済ませた記録を兼ねない。** 指摘へ答えるのにこの宣言を使っても、その指摘は完了の前に
`対応済み` として片付ける必要がある。

**`[停止: 応答]` は作業を先送りする口実にはならない。** 調べるための読み取りは答えるうちだが、
**成果物へ手を出した手番——編集・サブエージェントへの委譲と継続・書き換えるコマンド——はこれに当たらない。**
指示を実行し終えたことは、その指示に答えたことにならない。**作業の区切りで報告したいことは、問われた
ことではない。** 問いに答えるために調べたのでなく手を出したなら、受けた指示に残りがある限り
止まらずに続ける——**続けてよいのはその範囲だけで、手を出したせいで応答を使えなくなったことは、
指示されていない作業へ進んでよい理由にならない。** 手を出したかを見る窓は次のユーザー発言まで
閉じないので、**その発言に対して応答はもう使えない**。受けたものが済んでいるなら完了を使う
——調べろ・確かめろと言われて調べ終えたなら、これに当たる。順序の指定(「まず」「先に」)は、済んだところで
止まってよいという意味ではない。**ただしユーザーが出した禁止や明示指定が作業を妨げているなら進まない**
——着手を禁じられている場合も、明示指定された設定を指定どおりでは続けられなくなった場合も、その
解除・変更を `[停止: 要判断]` で諮る。**停止の区分は自分の状態の説明であって、手番を返す
許可証ではない。**

**残った指示を完了として宣言し直さない**——完了を宣言してよいのは、ユーザーが前の指示を明示的に
取り消したか、前の指示にもう未了が無いときだけである。

**宣言を書けることは、完了の裏付けにならない。** 完了の宣言は、受け持った範囲のステップと、受けた
発言の一つ一つに、済ませた記録が在るかを突き合わせて判定され、未達なら弾かれる。弾かれたときに
取るべき行動は、名指しされた項目を進めることであって、宣言の書き方を変えることではない。
**この突き合わせが届かないもの——記録には残るが実際には片付いていないこと——についても、本節が定める
完了の範囲は変わらない。** 機構が通したことは、宣言してよいことの裏付けではない。
