# 着手判断規約

自分の判断で作業へ着手してよいか、始めた作業を続けてよいかの**正本**とする。着手すると決めた作業を
どの手順で進めるかは定めない。見つけた不備がどうなっていれば終わったと言えるかは
[不備の後始末規約](defect-followthrough.md)、ユーザーが明示した指定をどこまで動かしてよいかは
[ユーザー指定の遵守規約](user-directives.md)を正本とし、本書はそれらへ委譲する。

## 1. 適用範囲

**着手するかどうかを自分で選べる作業**を対象とする。未解決事項・残課題の一覧に載っている項目、
自分の走査や動作確認で見つけた不備、思いついた改善が該当する。

**ユーザーが名指しで依頼した作業は対象外。** 依頼そのものがユーザーによる価値の判断であり、
本書を根拠に打ち切らない。依頼された作業の価値に疑いがあるなら、疑いを述べたうえで依頼どおり
進める(指定を自分の判断で動かさないことは[ユーザー指定の遵守規約](user-directives.md)が正本)。

## 2. 困りごとを一文で言えないなら着手しない

着手前に、**誰が・どの操作で・どう困るか**を一文で言う。言えないなら着手せず、**打ち切ると決めて
理由を残す**([対処の三つの終わり方](defect-followthrough.md#2-対処の三つの終わり方))。言えないこと
自体はユーザーに諮る理由にならない——諮ってよい場面の定めは同節が正本で、本書は定めない。

- **一覧に載っていることは着手してよい理由にならない。** 未解決事項・残課題として記録されている
  項目は「まだ判断していない」という意味であって、「やるべき」という意味ではない。記録されて
  いることを価値の判断と取り違えない。
- 一文は**困る相手と経路まで**言う。「表示が乱れる」では足りず、誰のどの操作でそれが起きるかを
  言う。言ってみて、その経路を通る利用者が居ない(自動処理の側は影響を受けない、人が触らない
  画面である等)と分かるなら、それは着手しない理由である。
- **安く直せることは価値の代わりにならない。** 手間が小さいことと、直す意味があることは別である。

## 3. 原因を測ってから対策を書く

**見当をつけただけの原因で実装を始めない。** 原因を測る前に書いた対策は、効かなければ実装・確認・
差し戻しがすべて無駄になり、効いたとしても何が効いたのかを確かめていない。

**測る手段が用意できないなら、実装ではなく判断へ進む**——打ち切ると決めて理由を残すか、ユーザーに
諮る([対処の三つの終わり方](defect-followthrough.md#2-対処の三つの終わり方))。測れないことは、
見当で書いてよい理由にならない。

## 4. 空振りしたら手段でなく価値を問い直す

調査・計測が無効に終わったら、**手段を作り直す前に、続ける理由がまだあるかを確かめる**。無効に
終わった時点で問うべきは「どう測るか」ではなく「そもそも測る価値があるか」である。手段の改良へ
直行すると、価値を問わないまま次の空振りへ進む。

**費やした手間は価値を上げない。** ここまで掛けたことは続ける理由にならない。空振りが続くときは、
手段の不備だけを疑わず、[§2](#2-困りごとを一文で言えないなら着手しない)の一文を言い直して
確かめる。
