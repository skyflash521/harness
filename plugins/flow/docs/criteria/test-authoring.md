# テスト記述規約

コミットして残るテストについて、**ケース1本ごとに示す根拠の正本**とする。

## 1. 適用範囲

- 対象: コミットして残るテストのケース。自動で走り、合否を返すものを指す。
- パラメータ化したテストは、入力1組を1ケースと数える。
- フィクスチャと期待値ファイルは、それを使うケースと一体で扱う。

## 2. ケースが示す根拠

**テストのケースは、1本ごとに下記2つの根拠のどちらかを示せるものを書く。** どちらも示せないケースは、
[§3](#3-根拠を要さない例外)の例外に当たるものを除いて残さない。根拠の形を取れても残さないケースは
[§4](#4-根拠の形を取れても残さないケース)が定める。

### 根拠1: 仕様の固定

外から観測できる約束——入出力の意味、エラー時の挙動、境界値、互換性の約束——の1件を、そのケースが
固定している。

- **ケースの名前がその約束を述べている。**
- **その約束を破る変更を入れると、そのケースが落ちる。** 入力が別の検査に掛かって同じ結果に
  なっているケースは、約束を固定していない。
- **約束1件につき1ケース。** 同じ約束に複数のケースを充ててよいのは、入力が互いに別の同値類に属する
  ——境界の内と外、空と非空など——ときに限る。

### 根拠2: 退行の検出

コードへの変更を1つ具体的に挙げられ、**その変更を入れるとそのケースが落ちる。**

- **挙げる変更は、実際に入れて確かめられる具体さを持つ**——「この比較を `<` から `<=` にする」
  「この分岐を消す」。「どこかが壊れたら」は根拠にならない。
- **挙げる変更は、既にある記述の1箇所を変えるものに限る**——比較や条件の反転、項や要素の脱落、
  一致の狭めと広げ。その入力だけを特別に扱う分岐を足す変更は根拠にならない。
- **挙げる変更は、外から観測できる振る舞いを変えるものに限る。** 内部の分割・呼び出し順・名前の
  変更のように、振る舞いを保つ変更は根拠にならない。
- **同じ変更を検出するケースが複数あるとき、その変更を根拠に残せるのは1本だけである。** 残すのは、
  判定の境界に最も近い入力のケースとする。
- 依存ライブラリ・OS・外部ツールの更新も変更に含む。ただし、自分のコードが頼っている挙動を変える
  更新に限る。
- 過去に起きた不具合を再現するケースは、その不具合を戻す変更を根拠にできる。

## 3. 根拠を要さない例外

根拠を示せなくても残してよいケースは、次の2類型に限る。

### 例外1: 未知の不具合を探すテスト

ファジング、ランダム入力、並行処理のストレス、別実装との突き合わせ。

- **確かめる性質が、外から観測できる約束である**——異常終了しない、往復で元に戻る、参照実装と
  一致する。
- **落ちたときに再現できる。** 乱数の種か失敗した入力が、失敗時の出力に現れる。
- **見つけた不具合は、固定した入力のケースとして根拠2で残す。**

### 例外2: 仕様化テスト

仕様の無い既存コードを、振る舞いを保ったまま作り変えるあいだ、今の出力を丸ごと固定するケース。

- **作り変える対象のコードに限る。**
- **作り変えを終えるコミットで、根拠を示せるケースへ置き換えるか、消す。**

## 4. 根拠の形を取れても残さないケース

- **コードの写し**——確かめている値が、分岐も状態も持たない1箇所の記述(定数、フィールドの素通し、
  単一の式)からそのまま決まるケース。`add(1, 1)` が `2` を返すことの確認がこれに当たる。
  **変えないと外へ約束した値を固定するケースは残してよい。**
- **自分のコードが頼っていない、言語・フレームワーク・依存ライブラリの動作の確認**——`1 + 1` が
  `2` であること、標準ライブラリの関数が文書どおりに動くこと。
- **テスト自身が設定した値を、テスト対象を経由せずに確かめるケース**——モックへ設定した戻り値を、
  そのモックを直接呼んで確かめること。
- **呼び出しの回数や順序の検証。** 回数や順序そのものが外から観測できる約束(課金 API を1回しか
  呼ばない、など)であるケースは残してよい。
- **型や言語の機構が既に保証していることの確認。**
- **確かめる内容が「例外が出ない」しかないケース。** 起動確認のように、それが約束そのものである
  ケースは残してよい。
