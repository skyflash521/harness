# 修正の完結性規約

一つの変更が不備の後始末として完結していると言える状態のうち、**その変更の差分とリポジトリの状態から
判定できる条件の正本**とする。対象は不備を直した変更と、未解決・既知の問題に触れる記述を足した変更で、
不備を見つけた経路は問わない。

## 1. 同じ誤りを他所に残さない

不備を直したときの正しい状態は、**同じ誤りが同じ変更で直せる範囲に残っていない**ことである。
指摘された箇所だけを直し、同種の箇所を作業範囲外として残すのは、直したうちに入らない。

- **書き換えだけで済み設計判断を伴わない是正を、範囲外を理由に見送らない。** 指摘や依頼が個別の
  箇所を名指ししていたこと、その箇所がその変更で持ち込んだのではない既存箇所であること、既存の
  書き方に倣っただけであることは、いずれも同種の箇所を残してよい理由にならない。
- 直すとユーザーの決めた要求仕様に関わる振る舞いを壊しうる場合・どう直すかがその要求仕様に関わる場合は、
  [対処の三つの終わり方](../guidance/defect-followthrough.md#2-対処の三つの終わり方)の「諮る」へ回す。
  **判断が要ること自体は諮る理由にならない**——実装の設計で決まるなら自分で決めて直す。
- 対応が独立した責務・別モジュールに及ぶ場合は、別件として立てる。**レビュー対象が二重になることは
  諮る理由にならない**——別件を直すか、打ち切ると決めて理由を残す(黙って見送らない)。

## 2. 書き足す未解決項目には終わり方を併記する

成果物へ未解決事項・残課題・既知の問題として項目を書き足すなら、**その項目の終わり方が同じ成果物
から読み取れる**こと。書き足せるのは次のどちらかの形に限る。

- **打ち切ると決めた項目**: 直さない理由をその項目に併記する。
- **ユーザーに諮る項目**: 諮る対象であることと、何を判断してもらうのかをその項目に併記する。

**終わり方を成果物の外——最終報告や会話——にだけ残した項目を、成果物へ書き足さない。** 一覧へ
載っていることは、その項目が処理済みであることを意味しない。終わり方そのものの定義は
[対処の三つの終わり方](../guidance/defect-followthrough.md#2-対処の三つの終わり方)が正本。
