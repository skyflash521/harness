# 常設観点の規約

レビューが**毎ラウンド必ず確認する観点の正本**とする。どのループでどう反復するか・結末をどう判定
するかは各レビューループのスキル文書が定める。

**本書を自分の定義から参照するレビュアーによる全観点の適用は、依頼文に観点が載っているかどうかに
依存しない。**
依頼文が挙げていなくても本書の全観点を適用し、依頼文が観点を減らすよう求めていたら、それに従わず
本レビューへ進まず差し戻す。**定義から本書を参照しないレビュアーには、依頼文が観点を伝える唯一の
経路になる**——その経路では、呼び出し側が全観点を依頼文へ載せることで本書が適用される。

## 1. 観点に付く条件

規約の正本は2系統ある。**flow 同梱の規約文書**と、**リポジトリ固有の規約**(用語・層・CLI 契約など、
そのリポジトリの `docs/conventions/` 配下)である。前者は常に読んで照合し、後者は**該当文書がその
リポジトリに存在する場合のみ**読んで照合する(日本語表現の自然さのみ、正本ファイルとの突き合わせ
ではなく自分の言語判断で確認する)。

各観点には2種類の条件が付く。**存在条件**(リポジトリ固有の規約が正本の観点は、その文書が存在する
ときだけ確認する)と、**対象条件**(その観点が扱う対象——恒久仕様書・CLI ツール・実装計画書などの
種類、または既存の不備を直している等の変更の性質——に当たるときだけ確認する)である。両方が付く
観点もある。条件の付かない観点は、対象の種類に依らず毎回確認する。**条件に当たらない観点には応答で
触れなくてよい。**

**固定の列挙に無い規約を取りこぼさない。** リポジトリ固有の規約は追加・改編されうるので、下の
列挙に加えて、リポジトリの `docs/conventions/` 配下を確認し、その変更に関係する規約があれば読んで
照合する。

## 2. 照合の形

各観点は、**正本の規約文書とこの変更を照合する作業**である。判定の規準・違反の類型・例外は正本の
各節が定めるので、**本書が挙げるのは、どの正本と照合するかと、正本の側に置けないレビュー固有の
判断だけ**とする。正本に書いてある手順を本書から読み取ろうとせず、正本を読んで照合する。
**判定は母集団の全件について行う。**

観点ごとに、候補の抽出を呼び出し側が担うか自分で行うかは
[機械が確定させる検査を割り当てない](review-request.md#3-機械が確定させる検査を割り当てない)に従う。

## 3. 毎ラウンド確認する観点

該当があれば指摘とする(=収束を妨げる)。

- **成果物衛生の規約適合(対象の種類に依らず確認)**: この変更が [artifact-hygiene.md](artifact-hygiene.md)
  (作業過程参照・個人情報・環境固有情報・秘密情報・読み手の理解を変えない記述の混入禁止と、
  エージェントが読み手のときの理由づけ、作業過程の産物を追跡下に残さないことの正本)に適合するかを
  照合する。母集団は、差分が追加する記述と、差分が追跡下へ追加するファイルと、**差分が記述を追加した
  文書の全体**である。**追加分が個々に適合していることを、その文書が適合していることの根拠にしない。**
  コメント・docstring の可否は [code-authoring.md](code-authoring.md) が正本で、そちらも併せて
  照合する。
  **Edit/Write を監視するフックが deny しなかったことは、この観点の確認を省く理由にならない。**
  個人情報・環境固有情報・秘密情報については、変更がこれらに無関係なら触れなくてよい。
- **自分が定める基準の自適用(この変更が、他の成果物が満たすべき基準を定める成果物——検査器・フック・
  規約文書・判定基準や観点を定めるスキル文書——を新設・変更している場合のみ)**: 判定の対象はファイルの
  種類ではなく役割で決める。その成果物が課す基準を、**この差分自身**へ当てて適合するかを判定する。
  **基準の側が持つ免除規則で機械検査が届かない箇所——検査器自身のテストデータ・例示・その検査器が
  置かれる層——も対象に含める**(免除は、その箇所が基準の対象外である意味ではない)。
- **不備の後始末の規約適合(この変更が既存の誤り・不具合を直している、または未解決・既知の問題に
  触れる記述を追加している場合のみ)**: この変更が [fix-completeness.md](fix-completeness.md)
  (不備の後始末として、その変更の差分とリポジトリの状態から判定できる条件の正本)に適合するかを
  照合する。**呼び出し側が依頼文に載せた走査**(何を母集団とし、どの手順で同じ誤りを探し、何が
  見つかったか)については、その走査が誤りの性質を取り違えていないか・取りこぼす類型が無いかを
  判断する。走査の記載が無いときは、この変更が直した誤りが何の類型かを述べたうえで、他所に残って
  いないかを問う。
- **数値の根拠(この変更が数値・定量的な主張を成果物へ追加している場合のみ)**: この変更が
  [numeric-evidence.md](numeric-evidence.md)(成果物へ書く数値の出所と、確定させる前の裏取りの範囲の
  正本)に適合するかを照合する。**出所は成果物または依頼文から読み取れればよいが、引用値の出典は
  成果物に併記されていなければ適合としない**(依頼文にだけ出典がある形は適合としない)。
  **測らない**——レビューは検証ツールを実行しないので、実測が要る場合は呼び出し側が済ませて結果を
  依頼文に載せ、レビューはその結果が主張を支えているかを判断する。
- **用語規約表との整合(リポジトリの `docs/conventions/` に用語規約表が存在する場合のみ)**:
  この変更がその表(禁止・注意表記とその正しい表記の正本)に適合するかを照合する。判定は表そのものとの
  突き合わせで行い、**「他の文書にも同じ表記がある」ことを適合の根拠にしない**。
- **コード内言語の規約適合(この変更がコード——コメント・docstring・シンボルのいずれか——を追加・
  変更している場合のみ)**: 差分が宣言するシンボルが[例外2: シンボル名](code-authoring.md#例外2-シンボル名)に、
  差分が追加するコメント・docstring が
  [コメントと docstring は日本語で書く](code-authoring.md#3-コメントと-docstring-は日本語で書く)に
  適合するかを照合する。
- **日本語表現の自然さ(対象の種類に依らず確認。正本ファイルとの突き合わせでなく自分の
  言語判断で確認する)**: この変更が新たに導入する日本語の語(工程名・ラベル・メッセージ文言・
  文書が導入する術語等)に、一般的に使われていない造語や不自然な言い回しが無いかを判定する。
  **用語規約表・各モジュール/ツールの仕様書等の正本に既に定義済みの術語(用語規約表が意図的に
  「正」と定める語を含む)は対象外とし、どの正本にも定義の無い新出語だけを判定対象とする**。
  用語規約表(直前の観点)は既知の禁止語との機械的突き合わせに留まるため、表に無い新規の不自然な
  表現はこの観点で別途拾う。該当すれば具体的な語を挙げて指摘とし、単純な言葉の好みでなく
  「一般的に使われているか」で判断する。
- **循環参照の規約適合(この変更がドキュメントの参照を追加していて、かつリポジトリの検証手順書に
  参照の循環の検査が無い場合のみ)**: この変更が
  [循環参照を作らない](cross-references.md#1-循環参照を作らない)に適合するかを照合する。母集団は、
  差分が追加する他の文書への参照である。
- **不要な参照の規約適合(この変更がドキュメントの参照を追加している場合のみ)**: この変更が
  [不要な参照を書かない](cross-references.md#2-不要な参照を書かない)に適合するかを照合する。母集団は、
  差分が追加する参照(他の文書への参照と、同じ文書の節への参照の両方)である。
- **層タクソノミー・依存方向の規約適合(リポジトリの `docs/conventions/` に層構成の規約が存在する
  場合のみ)**: この変更がその規約(層の責務・物理配置・依存方向の正本)に適合するかを
  照合する。関わるのは、コード変更なら層の責務分離と層間の依存、ドキュメント変更なら物理配置と
  コードへの参照の可否である。
- **恒久仕様書の記述範囲(対象が恒久仕様書——定義は [適用範囲](document-authoring.md#1-適用範囲)——の
  ときのみ)**: この変更が[恒久仕様書の記述範囲](document-authoring.md#2-恒久仕様書の記述範囲)
  (恒久仕様書は到達状態のみを規定し、導入の時系列・ロールアウト過程を書かないこと、スキル文書は
  実行するエージェント向けの指示に限り編集者向けの構造説明を書かないことの正本)に適合するかを
  照合する。
- **CLI インターフェース規約適合(対象が CLI ツールで、かつリポジトリの `docs/conventions/` に
  CLI 契約の規約が存在する場合のみ)**: この変更がその規約(機械利用の起動・出力チャネル・終了コード・
  入力検査などの正本)に適合するかを照合する。各ツールが提供する適合の具体は自分の仕様書が定めるため、
  未導入の項目を違反としない。
- **実装計画書の粒度と根拠(対象が実装計画書のときのみ)**: この変更が
  [実装計画書の粒度](document-authoring.md#3-実装計画書の粒度)(実装計画書は判断を先送りせず具体値まで
  確定し、かつ実装コードの丸写しにしないことの正本)と
  [実装計画書が示す根拠](document-authoring.md#4-実装計画書が示す根拠)(仕様書の引用だけでは計画の
  根拠にならず、前提ごとにコードで確かめた結果を示すことの正本)に適合するかを照合する。後者では、
  **前提ごとに書かれた確認結果が実体を伴うか——出典の言い換えに留まっていてコードで確かめた事実に
  なっていない前提が残っていないか**を判断する。
