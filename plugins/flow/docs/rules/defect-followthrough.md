# 不備の後始末規約

作業の過程で見つかった不備(誤り・不具合・積み残し)について、**どうなっていれば対処済みと言えるか
の正本**とする。不備をどの検査でどう見つけるかは定めない。参照の書き方は
[cross-references.md](cross-references.md)、成果物への混入禁止は
[artifact-hygiene.md](artifact-hygiene.md)、文書種別ごとの記述範囲・粒度は
[document-authoring.md](document-authoring.md)、直すか打ち切るかを分ける価値の判断は
[work-initiation.md](../guidance/work-initiation.md) を正本とし、本書はそれらへ委譲する。

## 1. 適用範囲

見つかった不備すべてを対象とする。ユーザーに指摘されたもの、自分の走査で見つけたもの、実行・
動作確認で踏んだもの、レビューで挙がったものを問わない。**見つけた経路は対処の要否を変えない。**

## 2. 対処の三つの終わり方

不備は次のいずれかの状態で終わっていること。

- **直した。**
- **打ち切ると決め、直さない理由が成果物または最終報告に残っている。**
- **ユーザーに諮り、その判断を待っている**(諮るとは、ユーザーの応答を待つために作業を止めることを
  いう。どの時点で止めるか——その場で止めるか、蓄積して区切りで止めるか——は実行中のスキルの規定に
  従う)。

**所在を報告して先へ進むことは、この三つのどれでもない。** 進行中の報告は後続の出力に流れ、
ユーザーが読む保証が無い。読まれる形で渡す手段は、作業を止めて応答を待つこと以外に無い。
よって、停止せずに報告へ書いただけの項目は**誰にも渡っていない**ものとして扱う。「作業範囲外だが
所在は報告した」で終えた項目は、対処されていない項目である。

**未解決事項・残課題の一覧へ書くことも、対処の代わりにならない。** 一覧へ載せる項目についても
上の三つのいずれかを同時に決める。一覧に載っていることは、その項目が処理済みであることを意味しない。

**一覧に載っていることは、その項目へ着手してよい理由でもない。** 直すと打ち切るのどちらを選ぶかの
判断は[着手判断規約](../guidance/work-initiation.md)が正本で、本書はそれへ委譲する。

**諮ってよい場面は、実行中のスキルの停止規定が定める。** その規定が停止を許さない場面では、
選べるのは「直す」か「打ち切ると決めて理由を残す」の二つであり、報告へ回すことは選択肢に入らない。

## 3. 同じ誤りを他所に残さない

不備を直したときの正しい状態は、**同じ誤りが同じ変更で直せる範囲に残っていない**ことである。
指摘された箇所だけを直し、同種の箇所を作業範囲外として残すのは、直したうちに入らない
——ユーザーに同じ指摘を繰り返させる。

- **書き換えだけで済み設計判断を伴わない是正を、範囲外を理由に見送らない。** 指摘や依頼が個別の
  箇所を名指ししていたこと、その箇所がその変更で持ち込んだのではない既存箇所であること、既存の
  書き方に倣っただけであることは、いずれも同種の箇所を残してよい理由にならない。
- 直すと壊れうる場合・どう直すかに判断が要る場合は、
  [対処の三つの終わり方](#2-対処の三つの終わり方)の「諮る」へ回す。
- 対応が独立した責務・別モジュールに及び、その変更に混ぜるとレビュー対象が二重になる場合は、
  別件として同じく「諮る」へ回す(黙って見送らない)。

## 4. 迂回は不具合の対処ではない

実行・動作確認で対象側の不具合を踏み、自分の道具・手順の側でそれを避けて先へ進むことはあってよい。
ただし**避けたことは、その不具合の対処ではない。** 踏んだ不具合は
[対処の三つの終わり方](#2-対処の三つの終わり方)のいずれかで終わらせる。

不具合の原因まで到達していたなら、**その原因が、既知の未解決事項として記録されている項目と同じ
ものかを突き合わせ、突き合わせた結果が記録に反映されている**こと。同じなら判明した原因を
その項目へ、別なら新規の項目として残す。自分の道具が困らなくなったことは、突き合わせを省く理由に
ならない。

**検査・ガードに止められたときは、避けること自体が禁じられる。** 検査が名指しした不備が成果物の側に
実在するならそれを直すのが対処だが、**不備が無いまま通すために成果物を書き換えることは迂回ですらない**
([通すために成果物を変えない](../guidance/guard-rejection.md#4-通すために成果物を変えない))。

## 5. 未解決を残したまま完了としない

計画・ステップ・作業を完了として記録・宣言してよいのは、**その範囲に、
[対処の三つの終わり方](#2-対処の三つの終わり方)のどれも決まっていない項目が無いとき**に限る。
動作確認で観測した挙動は、記録した時点では未対処である。一覧に載っていることを完了の根拠にしない。
