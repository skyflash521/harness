# 数値の根拠規約

成果物へ事実として書く数値と、その数値に依拠して確定させる判断について、**何をもって裏取りが
済んだと言えるか、裏取りできていないものをどう書くかの正本**とする。どう測るか(手段の作り方・
計測の進め方)は定めない。

## 1. 適用範囲

- 対象: コミットして残る成果物(仕様書・コード内のコメント・テスト・コミットメッセージ)と、
  ユーザーへ渡す最終報告に、**事実として読める形で書く数値**。容量・所要時間・回数・上限値が
  典型で、数値以外でも実行して初めて分かる事実は同じ扱いとする。**待っている処理が実行中かどうかも
  この種の事実**で、観測せずに述べてよい理由は無い。
- 対象外: 実行でも計算でも確かめようのない記述(設計の意図・規約の定め・外部から与えられた要求)。
- **コードを読めば確定する事実は本書の対象ではない。** 本書が扱うのは読解では確定しない数値である。

## 2. 出所を言えない数値は書かない

**書く前に、その数値が実測値・導出値・引用値・見積りのどれかを自分の中で確定する。** どれとも
言えない数値は書かない。

- **断定形で書いてよいのは、実測値・導出値・引用値**である。導出値は定義・仕様・書式から一意に
  決まり、[§3](#3-計算で確定できるものは計算で確定させる)のとおり導出を示せるものをいう。
- **引用値は出典とともに書く。** 仕様・規格・既存の計測結果のように**確かめられる出典**から引いた
  値は、その出典を示せるなら断定形でよい。出典を示せない引用は引用値ではなく、見積りとして扱う。
- **見積りを成果物へ残さない**。見積りとは、その量を決める項を漏れなく挙げられるとは
  言えないまま行った計算をいう。確定前の作業の中で扱うときは、
  見積りである旨と何から出した値かを併せて書き、確定までに裏取りするか落とす。
- **丸めの表現は、裏取りしていないことを覆う手段ではない。** 裏取りしたうえで丸めるのはよい。
  禁じるのは、見積りを「おおよそ」「程度」「〜を超えうる」で包んで断定として通すことである。
  そう書きたくなった時点を、裏取りが済んでいない合図として扱う。

## 3. 計算で確定できるものは計算で確定させる

**計算で一意に決まる数値を、わざわざ実測させない。** 定義・仕様・書式から決まる値(規格が定める
上限、固定長の書式が占めるバイト数、閉じた式で決まる回数など)は、導出を示せば確定であり、実測は
裏取りの条件ではない。

**確定と言える条件は、その量を決める項を漏れなく挙げられること**である。挙げられるなら計算で
確定させ、**導出(どの定義・仕様・項から出したか)を根拠として示せるようにしておく**。導出を
示せないものは、確定ではなく見積りである。

## 4. 漏れが無いと言い切れない量は計算で代用しない

**確定を妨げるのは、実行環境の実装に依存することそのものではなく、全項を挙げ切れないことである。**
処理系の内部表現・確保の粒度・途中で生じて捨てられる分・実行時の回収の挙動が絡む量はその典型だが、
**その実装が定める全項と式を示せるなら、実装に依存する量でも
[§3](#3-計算で確定できるものは計算で確定させる)の導出として扱ってよい**(実装依存であることは、
実測を課す理由にならない)。

項が閉じないまま行った計算は、[§3](#3-計算で確定できるものは計算で確定させる)の確定には当たらない。

- **判断に効く量が複数あるとき、計算は自分が選んだ量だけを出す。**
- **計算値が実測値に近かったことは、その計算が確定だったことを示さない。**

## 5. 判断を決める数値は確定させる前に裏取りする

上限値・閾値・既定値をある数値だけを理由に選んだなら、**その数値が裏取りできていない限り、選んだ
値も裏取りできていない**。根拠が見積りのままの設計値を、確定した決定として成果物へ書かない。

- 裏取りの手段は[§3](#3-計算で確定できるものは計算で確定させる)の導出でも実測でもよい。**導出で
  確定できないものだけを測る。**
- **測る費用が小さいことは、測らない理由を消す。** 導出で確定できず、使い捨てのスクリプト1本と
  数分で測れるものを、判断の根拠にしながら測らないのは、費用の判断ではなく省略である。
- **どちらの手段も用意できないなら、その数値は成果物へ残さない**。裏取りできないことは、見積りを
  断定として書いてよい理由にならない。

## 6. 裏取りできていない数値は確定させない

裏取りできていない数値を、成果物へ残したまま確定させない(コミットしない。最終報告で結論として
述べない)。**選べるのは、裏取りしてから書くか、その数値を書かないかの二つである。**

- **書かないとは、値を落として記述を成り立たせることをいう。** その数値に依拠しない書き方
  (何が起きるかの向き・条件だけを述べる)へ直すか、その数値を唯一の根拠にしていた設計判断ごと
  見送る。
- **見積りと分かる形へ直すことは、確定させてよい理由にならない。**
- **この禁止をユーザーに諮って回避しない。** 裏取りできない数値を残すかどうかは判断を仰ぐ事柄では
  なく、残さないことで閉じる。確定させた後で「これは見積りだった」と述べることは、開示ではなく
  後始末であり、同じく認めない。
