# 成果物衛生規約

リポジトリに残すすべての成果物に、後から参照できない作業過程の記述・個人情報・環境固有情報・
秘密情報・読み手の理解を変えない記述(自明な内容、コードや外部仕様の書き写し、採らなかった案の
比較検討など)と、読み手がエージェントの文書ではその行動を変えない理由づけを混入させないための
規約。作業過程の産物そのもの(使い捨てのスクリプト・一時ドキュメント)を追跡下に残さないことも
含む。本書は**混入を禁じる対象と、正しい置き換え方の正本**とする。

## 1. 適用範囲

- 対象: コミットして残るすべての成果物 — コード・コメント・docstring・テスト・仕様書・
  コミットメッセージなど、種類を問わない。**追跡下へ置くファイルそのものも対象**。

## 2. 作業過程参照の混入禁止

**後から参照できない作業過程の記述**を成果物に残さない。

**禁止する記述:**

- ステップ番号(「Step 3」など)・レビューのラウンド番号。
- **記述理由を作業時点に依存させる日付**(作業日・レビュー実施日など)。
- 「改修前」「改修後」「今回」などの、作業の時点に依存する相対参照。
- **恒久仕様でない一時ドキュメント**(実装計画書・設計メモ・レビュー記録など、コミット後に
  削除されうるもの)への参照。**その見出し・ステップ名も、採番を伴わなくてもこれに当たる。**
- **後の工程で外す前提の一時的な印**(未実装のテストを無効化する理由文字列など)。

**列挙は例示であって語形の一覧ではない。** 上記の既知の語に当たらないことは適合の根拠にならず、
判定は**その記述の出所が成果物の外(計画書・レビューの会話・作業メモ)にあるか**で行う。

**対象外(混入ではない):**

- 仕様上の期日・データ形式の例・テストの固定日など、作業時点に依存しない日付。

**正しい書き方:** 挙動を自己完結で述べる。基準となる別状態を指さず、その記述だけで意味が通る
ようにする(例: 「None なら全初期値を試す」と書く。「改修前と同一」とは書かない)。

## 3. 個人情報・環境固有情報の混入禁止

**個人を特定しうる情報や作業環境固有の情報**を成果物に残さない(特定の形に限定しない)。

**禁止する情報(これらに尽きない):**

- ユーザー名・実名・メールアドレス・ホスト名/マシン名。
- ドライブ文字付きやホームディレクトリを含む実絶対パス、ローカルのディレクトリ構造を晒すパス。
- 秘密情報(API キー・トークンなど)。

**対象外(混入ではない):**

- **リポジトリ相対パス**(`scripts/…` のような、そのリポジトリのルートからの相対パス)や
  `file:line` 参照。本節が定めるのは個人情報・環境固有情報として混入でないことのみで、コードと
  ドキュメントの間で参照してよいかは、リポジトリが層構成の規約を持つ場合その文書が別途定める。

**正しい書き方:** リポジトリ相対パスや汎用のダミー値(`/repo`・`user`・`example.com` など)に
置き換えて自己完結させる。

## 4. 読み手の理解を変えない記述の混入禁止

**コードや文脈から自明なこと、既出の記述が既に保証していることを言い直すメタ注記、正本が別に
ある内容の転記、説明する対象がその場に無い記述**を成果物に残さない。

**適用範囲:** 本節が対象とするのは**文書とコミットメッセージ**である。

**適用の限定:** 下記のうち変更履歴の叙述・外部仕様の転記・採らなかった案の比較検討の3類型は、
**変更そのものを主題としない文書の本文**を対象とする。コミットメッセージ・CHANGELOG・移行手順書など、
変更や検討を記述すること自体が役割である成果物は、この3類型の対象外とする。

**禁止する記述:**

- コードや文脈から自明な内容(例: `.gitignore` 内に「コミットしない」と書く)。
- **その文書が定めないことの、委譲先を示さない宣言**(「〜は定めない」「〜は扱わない」)。冒頭の
  主題の宣言で範囲は決まっており、外れるものを数え上げても読み手の理解は変わらない。どこが正本かを
  示す委譲(「X は〈正本〉が定める」)と、**その文書の判定を変える対象外の明示**は、これに当たらない。
- 構造や既出の記述が既に保証していることを言い直すメタ注記(例: 参照先を「ここを正とする」と
  明示した直後に「ここに重複させない」と付す)。
- 変数名・式・処理内容の逐語的な書き写し(例: 関数の処理を1行ずつ言い換えて並べる)。
- **変更履歴・過去の実装の叙述**のうち、現在の挙動の理由づけとして働かないもの(「以前は〜して
  いた」「〜から移行した」とだけ述べる類)。正本は git の履歴とコミットメッセージ。
- **ライブラリ・外部 API の仕様の転記**のうち、同じく現在の挙動の理由づけとして働かないもの
  (引数の意味・戻り値・バージョンごとの挙動などの書き写し)。正本は当該ライブラリの文書。
- **採らなかった案の比較検討**(検討した代替案とその却下理由の列挙、まだ書いていない対応の予告)。
  成果物が述べるのは到達した設計とその理由であって、到達しなかった案ではない。検討の過程の
  置き場は一時ドキュメントで、実装が済めば役目を終える。**「調べた内容が失われる」ことは、
  それ自体では残す理由にならない**——残すかどうかは、その記述が無いと読み手が現在の挙動を誤るかで
  決まる。

**対象外(混入ではない):**

- 「なぜ」や非自明な背景——隠れた制約、不変条件、特定の不具合の回避策、読み手が驚く挙動——を
  説明する記述。**採った設計の理由もここに含まれる**(採らなかった案の理由と分かれる)。読み手が
  エージェントである文書では、この対象外の範囲を
  [§5](#5-エージェントが読み手のときの理由づけ)が狭める。
- 履歴・外部仕様に触れていても、現在の挙動の理由を説明する記述。互換性要件(旧形式のデータを
  読めるようこの分岐を残す)・回帰の防止理由(過去の不具合を検査で押さえる説明)・ライブラリの
  非自明な罠の指摘がこれに当たる。
- **現在の挙動の限界**(何を検出しないか・何を保証しないか)。禁じているのは、その限界に至るまでに
  比較した案の一覧のほうである。

**正しい書き方:** 書く前に、その記述を消したときに読み手の理解が変わるかを自問する。変わらないなら
書かない。判定は一文単位でなく**段落・節の単位**で行う。ただし必要な「なぜ」が一文でも入っていれば
全体が適合、とはしない——**その「なぜ」を保ったまま削れる叙述・転記が残っているなら、その部分が
混入**である。説明は、それが説明する対象の隣に置く。
離れた場所へ集約すると、対象を失った説明と、説明を失った対象の両方ができる。

## 5. エージェントが読み手のときの理由づけ

実行するエージェントが読み手である文書——スキル文書・エージェント定義・エージェントが従う規約文書
——に書いてよい理由づけは、**その理由が無いとエージェントの行動が変わるもの**に限る。理由が無くても
指示のとおり実行できる箇所に、その指示の理由を添えない。

**行動が変わる(書いてよい):**

- **指示が事例を覆いきれず、当てはめの判断がエージェントに残る。** 列挙に無い事例をどう扱うかの
  規準が、その理由でしか与えられていない。
- **理由が無いと、指示より良く見える別の行動へ逸れる。** 指示が非効率・迂遠に見える、または形だけ
  満たして目的を外す抜け道がある。

## 6. 作業過程の産物を追跡下に残さない

使い捨ての計測・検証スクリプトと、恒久仕様でない一時ドキュメント
は[スクラッチ置き場](adoption.md#2-スクラッチ置き場)に置く。**リポジトリの追跡下へ置かない。**
