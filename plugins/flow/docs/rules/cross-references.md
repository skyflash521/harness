# ドキュメント参照規約

ドキュメントと、その節への参照を書いてよいか・どの向きに書くか・どう書くか、および編集後にその
参照が壊れていないかをどう確認するかをまとめる。コードへの参照の可否は、リポジトリが層構成の
規約を持つ場合その文書が定める。

## 1. 循環参照を作らない

辿って元の文書へ戻る経路を作らない。双方向の参照が要るなら、どちらが正本かを決めるか、共通部分を
別の文書へ切り出す。

## 2. 不要な参照を書かない

内容が依存していない文書・節は参照しない。参照を外しても記述の意味が決まるなら、依存していない。

## 3. 参照は必ずMarkdownリンクとして書く

- **節参照**: 見出しを指す言及は必ず**アンカー付きMarkdownリンク**として書く。
  **見出しを指す言及はすべて節参照であり、見出しの番号の有無・種類を問わず同じ規則に従う**
  ——「N章」「(N.M)」「N.M節」「N.M の…」のように番号だけで指す書き方も、「A〜C」のように英字
  見出しを指す書き方も、無番号見出しを名前だけで指す書き方も使わない。例外: リポジトリ外の文書(SemVer仕様など)を指す参照はリンク化しない。
- **ファイル相互参照**: 節番号を伴わないファイル相互参照も、必ずMarkdownリンクとして書く。
  地の文やコードスタイル表記で相対パス・ファイル名をそのまま書かない。
- **見出しでない箇所を離れた場所から参照しない**: 別の節・別のファイルにある手順の項番・箇条書きの
  項番・表の行などは、アンカーを持たずリンクにできない。番号で指す(「B の手順2」)のも項目名で指す
  (「リンク検査で確認する」)のも同じく参照にあたる。**リンクにできないものは離れた場所から参照しない**——参照したい
  内容は見出しへ昇格させてリンクするか、参照せずに済むようその場で述べる。同じ節の中で直前・直後の
  内容を「上記」「次の」と指すのは、読み手の目の前にあり離れた参照ではないので対象外。

## 4. リンクの書き方(検出可能性を保つ)

リンクを書くときは、以下を守る。

- **リンクを入れ子にしない**。既存のリンクに節参照を足すときは、そのリンクの表示テキストへ取り込むか、
  独立したリンクとして並べる。
- **リンク先は参照元からの相対パスで書く**。
- **実在しない特定ファイルを、実在するかのような具体名で書かない**。命名パターンの例示や、
  各モジュール/ツールに共通する一般的な言及(「各ツールの README」等)は、実在する1ファイルを
  指すかのような具体的なファイル名を書かず、`<モジュール>.md`・`<ツール>/README.md` のように
  `<...>` を使ったプレースホルダー表記にする。
- **見出し本文に意図しないリンク構文を作らない**。見出しの本文中で `[...]`(空でも中身があっても)の
  直後に空白なしで `(...)` を続けると、地の文のつもりでもMarkdownのリンク構文として解釈される
  (例: `parts[](説明)` は空リンクとして解釈され、意図した表示にならない)。このような並びが
  避けられない場合は、`` `parts[]` `` のようにバックティックで囲むか、`[]` と `(` の間に半角
  スペースを1つ挟む。
- **YAML frontmatter(ファイル先頭の `---` で挟まれた領域)で他の文書を参照しない**。
  参照は本文に置き、frontmatterでは文書名を出さずに内容を述べる。

## 5. 適用対象と機械チェックの範囲

本書の規則は恒久ドキュメント(ツール/ライブラリ仕様、フォーマット仕様、README、プロジェクト規約、
エージェント手順書)に適用し、一時文書(実装計画書・設計メモ・作業ログ)は対象外。

**何をどの検査で確認するかはリポジトリの検証手順書([導入契約 1](adoption.md#1-検証手順書))が
定める**。ただし機械検査に載せられる範囲には原理的な限界があり、**`§N` 以外の表記による節参照
(「N章」「(N.M)」「N.M節」等)、離れた場所からの非見出し参照、および[§2](#2-不要な参照を書かない)の
依存の判定は、値との区別や意味の判断が要るため機械検査できない**——検査を通過してしまうので、
書いた本人が確認する。[§1](#1-循環参照を作らない)の循環は経路の有無で決まるので機械検査に載る。
