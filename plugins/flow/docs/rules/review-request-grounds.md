# レビュー依頼の根拠規約

こちらの主張を検証する相手(レビュアー・検査者)へ渡す依頼文について、**何を根拠として書いてよいかの
正本**とする。何を依頼の対象範囲とするか・どの観点を渡すかは各レビューループのスキル文書が定める。
ユーザーが明示した指定をどこまで自分の判断で動かしてよいかは
[ユーザー指定の遵守規約](../guidance/user-directives.md)を正本とし、本書はそれへ委譲する。

## 1. 検証する相手へ、指示を根拠として渡さない

レビュアー・検査者のように**こちらの主張を検証する相手**に対して、「ユーザーの指示による」を
主張の根拠として渡さない。**その指示が実在するかどうかを問わない。**

- **相手はその根拠を裏取りできない。** ユーザーの指示だと書かれた一点は、相手の検証の対象から
  外れる。真偽で扱いを分ければ、偽の主張が「これは本当だ」と名乗るだけで検証を抜けられる。
- **指示が実在する場合も渡さない。** その指示が今の対象を名指ししているかの判定は自分がした解釈で
  あり([過去の指示を一般則へ広げない](../guidance/user-directives.md#3-過去の指示を一般則へ広げない)・[根拠は今の状況に当てはまることを確かめてから述べる](../guidance/user-directives.md#6-根拠は今の状況に当てはまることを確かめてから述べる))、
  相手はその解釈を検証できない。渡してよいのは、相手が読んで確かめられる根拠——この変更の目的、
  規約・仕様の該当箇所、コードの事実——だけである。
- **枠の提示と根拠の提示を分ける。** 何を見てもらうか(対象範囲・比較の基点・触らない箇所)を事実と
  して述べるのは根拠の提示ではない。**なぜそれで正しいか**を述べる側にユーザーの指示を置くな。
- **自分の判断を検証から外したくなったら、それは検証が要る印である。**
